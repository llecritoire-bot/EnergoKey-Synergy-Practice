# Энергоключ

**Version 1.0.0**

«Энергоключ» — единый учебный Unity-проект для последовательного выполнения УП.ПМ.12, ПП.ПМ.12, УП.ПМ.13 и ПП.ПМ.13 колледжа / Университета «Синергия». Это простая 2D top-down arcade: игрок собирает все энергетические кристаллы, избегает статических опасностей и только после этого входит в открывшийся выход.

Персональные данные студента и титульные данные в проект не внесены.

## Среда проекта

| Параметр | Значение |
|---|---|
| Unity | **6000.6.2f1** (Unity 6.6) |
| Шаблон | 2D |
| Язык | C# |
| Ориентация | landscape; разрешены обе landscape-ориентации |
| Базовое разрешение UI | 1280×720, Canvas Scaler `Scale With Screen Size`, match 0.5 |
| Версия продукта | 1.0.0 |
| Сохранения | локальные `PlayerPrefs` через `SaveService` |

Открывать проект нужно именно в `6000.6.2f1`. Значение зафиксировано в `ProjectSettings/ProjectVersion.txt`. Импорт или сохранение проекта более старым Editor может необратимо изменить сцены, сериализованные assets и настройки.

## Подготовка и запуск в Unity Editor

1. В Unity Hub выберите **Open / Add project from disk** и укажите корневую папку `EnergoKey`, в которой находятся `Assets`, `Packages` и `ProjectSettings`.
2. Убедитесь, что Hub запускает Editor `6000.6.2f1`, и дождитесь окончания импорта.
3. Проверьте Console. До записи доказательств не должно оставаться красных ошибок компиляции или выполнения.
4. Если полный набор сцен ещё не создан, выполните **EnergoKey → Build Complete Three-Level Game**. Команда создаёт bootstrap-сцены `MainMenu`, `LevelSelect`, `Level1`, `Level2`, `Level3`, `Prototype` и записывает их в Build Settings в таком порядке.
5. Выполните **EnergoKey → Prepare Final Visual Style**, чтобы настроить импорт финальных авторских PNG и обновить четыре обязательных prefab.
6. Откройте `Assets/Scenes/MainMenu.unity` и нажмите Play. `MainMenu` — точка входа полной версии; `Prototype` сохранён как отдельный этап УП.ПМ.12.

Сцены намеренно содержат объект `SceneBootstrap`: иерархия игрового мира и UI создаётся при запуске по имени активной сцены. Код построения находится в `Assets/Scripts/Core/SceneBootstrap.cs`.

Для автоматического вызова Builder в целевом Editor предусмотрены методы:

```text
EnergoKeyProjectBuilder.BuildFullGameBatch
EnergoKeyProjectBuilder.PrepareFinalStyleBatch
```

При batchmode всегда указывайте абсолютный путь именно к Unity `6000.6.2f1`, `-projectPath` и отдельный `-logFile`. Код возврата и лог необходимо сохранить как фактическое доказательство; наличие метода само по себе не подтверждает успешную сборку.

## Сцены и экраны

| Сцена | Назначение |
|---|---|
| `MainMenu` | главное меню, лучший результат, переходы к выбору уровня, обучению, настройкам и экрану «Об игре» |
| `LevelSelect` | выбор доступного уровня; уровни 2 и 3 блокируются до соответствующих побед |
| `Level1` | простой маршрут: 3 кристалла, 2 опасности |
| `Level2` | более сложное расположение: 4 кристалла, 4 опасности |
| `Level3` | наиболее сложный маршрут: 5 кристаллов, 6 опасностей |
| `Prototype` | отдельный рабочий прототип этапа УП.ПМ.12 |

В игровой сцене предусмотрены HUD, Pause, Victory и Defeat. Settings, Tutorial и About доступны из меню. После победы на уровне 3 показывается финальный результат и предлагается вернуться в меню; сцены или перехода к уровню 4 нет.

## Правила игры

- В начале каждой попытки у игрока 3 жизни.
- Кристалл исчезает и засчитывается один раз.
- Выход остаётся закрытым, пока не собраны все кристаллы. Попытка войти в закрытый выход даёт текстовую и звуковую обратную связь.
- Опасность отнимает одну жизнь и возвращает игрока к стартовой точке. Уже собранные в текущей попытке кристаллы после повреждения остаются собранными.
- Ноль жизней открывает Defeat. Restart перезагружает уровень, сбрасывая временное состояние попытки, но не общий прогресс.
- Все кристаллы плюс вход в открытый выход открывают Victory.
- Итоговый счёт вычисляется как `collectedCrystals × 100 + remainingLives × 50`. Лучший результат обновляется после победы.

## Управление

- На экране: удерживайте кнопки со стрелками вверх, вниз, влево и вправо.
- В Unity Editor: WASD или клавиши со стрелками.
- Пауза: экранная кнопка Pause; продолжение — кнопка «Продолжить» на панели.

Editor-only клавиши ускоряют подготовку реальных доказательств, но не заменяют обычное прохождение и не входят в release-сборку:

| Клавиша | Действие в Play Mode |
|---|---|
| F2 | открыть уровни 1–3 в локальном сохранении для подготовки Level Select; при открытом выборе уровней экран обновляется сразу |
| F3 | собрать все оставшиеся кристаллы текущего уровня |
| F4 | показать победу, предварительно собрав оставшиеся кристаллы |
| F5 | показать поражение |
| F6 | вызвать попытку использовать выход, включая сообщение закрытого выхода |
| F8 | включить/выключить имитацию Safe Area в Editor |

Горячие клавиши предназначены только для постановки состояния перед настоящим снимком Game View. Они не являются доказательством прохождения теста: фактическое действие, наблюдение и путь к снимку всё равно записываются в `EVIDENCE`.

## Прогресс и ключи сохранения

`Assets/Scripts/Save/SaveService.cs` использует четыре производственных ключа:

| Ключ PlayerPrefs | Тип / значение по умолчанию | Что хранит |
|---|---|---|
| `energokey.unlockedLevel` | int / `1` | максимальный открытый уровень, ограниченный диапазоном 1–3 |
| `energokey.bestScore` | int / `0` | лучший итоговый счёт |
| `energokey.masterVolume` | float / `0.8` | общая громкость 0–1 |
| `energokey.tutorialSeen` | int / `0` | `1`, если обучение завершено или пропущено |

Повтор уровня не удаляет эти ключи. Служебный сброс прогресса для разработки удаляет открытый уровень, лучший счёт и отметку обучения, но сохраняет выбранную громкость. Тестовый код Editor использует изолированные ключи и не должен менять производственные сохранения.

## Обучение

При первом запуске автоматически открываются три карточки:

1. **Управление** — экранные кнопки и вспомогательная клавиатура в Editor.
2. **Особое правило** — сначала собрать все кристаллы и только затем идти к выходу.
3. **Завершение и ошибка** — опасности, потеря жизни, победа и поражение.

Кнопка «Пропустить» и завершение карточек устанавливают только `tutorialSeen`; рекорд и открытые уровни не сбрасываются. Кнопка «Как играть» всегда повторно открывает обучение с карточки №1.

## Пауза и потеря фокуса

`PauseController` устанавливает `Time.timeScale = 0`, поэтому движение и игровой таймер останавливаются. Панель появляется плавно с использованием `Time.unscaledDeltaTime`; на время перехода повторные клики блокируются. У скрытой панели отключаются `interactable` и `blocksRaycasts`, поэтому она не должна перехватывать ввод.

При потере фокуса окна или сворачивании приложения обработчики `OnApplicationFocus` / `OnApplicationPause` автоматически включают паузу. Возврат фокуса не должен самовольно продолжать игру: пользователь нажимает «Продолжить».

## Адаптивный UI и Safe Area

Целевые контрольные форматы:

- 1280×720 — 16:9;
- 1440×720 — 18:9;
- 1024×768 — 4:3.

`SafeAreaAdapter` применяет `Screen.safeArea` к корневому `RectTransform`. В Editor клавиша F8 переключает нормализованную имитацию безопасной области 6% / 6% / 88% / 88%. Это только имитация для проверки компоновки и не выдаётся за тест на физическом устройстве.

Для трёх разрешений рекомендуется снимать один и тот же экран и состояние, чтобы сравнение anchors было проверяемым. Фактические кадры сохраняются под именами из `Documentation/03_SCREENSHOT_MATRIX.md`.

## Evidence и проверка комплектности

Основные файлы доказательств:

- `EVIDENCE/TEST_RESULTS.md` — отдельные Т01–Т16 для ПП.ПМ.12 и точные Т01–Т16 ПП.ПМ.13;
- `EVIDENCE/USER_TEST.md` — протокол пользовательской/самостоятельной проверки;
- `EVIDENCE/REPORT_DATA.md` — фактические данные для будущих отчётов;
- `EVIDENCE/FILE_MANIFEST.md` — состав и проверенные свойства файлов;
- `EVIDENCE/FINAL_STATUS.md` — построчная сверка с acceptance checklist;
- `EVIDENCE/MISSING_EVIDENCE.md` — всё, что осталось выполнить вручную;
- `EVIDENCE/screenshots/` — реальные снимки с именами из матрицы.

После подготовки полного проекта можно запустить read-only проверку:

```text
python3 Tools/verify_deliverable.py
```

При необходимости путь к другой копии матрицы передаётся первым аргументом. Скрипт сообщает `PASS`, `FAIL` и `NOT VERIFIED`, но не запускает Unity и не превращает наличие файла в доказательство игрового поведения.

## Сборка приложения

1. Сначала выполните две команды меню Builder и откройте `MainMenu`.
2. Откройте **File → Build Profiles**.
3. Убедитесь, что сцены включены в порядке `MainMenu`, `LevelSelect`, `Level1`, `Level2`, `Level3`; `Prototype` можно оставить для учебного архива, но он не должен быть стартовой сценой release-сборки.
4. Выберите установленный целевой модуль. Для Android нужны Android Build Support, SDK/NDK и OpenJDK той же установки Unity.
5. Соберите в каталог `Build/` вне передаваемого ZIP и сохраните фактический лог сборки в Evidence.
6. Запустите полученную сборку и повторите критические проверки; успешная компиляция Editor не заменяет запуск build.

Android-сборка и тест на физическом мобильном устройстве не считаются выполненными без реального build-лога и запуска.

## Git

Репозиторий является локальным. **Реального GitHub/GitLab remote URL сейчас нет**, поэтому адрес публикации в документации не указывается и не придумывается. Перед передачей преподавателю нужно либо реально опубликовать репозиторий, либо передать локальный Git-архив согласованным способом.

История должна сохранять отдельные этапы прототипа, трёх уровней, состояния до оформления, финального стиля, Profiler до оптимизации и release. Фактические имена тегов и hashes следует получать командами Git только после их создания, а не копировать из примера технического задания.

Итоговый полный hash проверенной версии:

```text
FINAL_VERIFIED_COMMIT_PLACEHOLDER
```

Этот токен необходимо заменить только после финального запуска, проверки новой копии репозитория, заполнения Evidence и фиксации единого итогового коммита.

## Текущая граница подтверждения и ограничения

- На машине подготовки не обнаружен требуемый Unity Editor `6000.6.2f1`; установлены только версии 2022.3. Поэтому импорт, Console, полный цикл трёх уровней, build и GUI именно в требуемой версии пока не подтверждены. Нельзя подменять такую проверку запуском в 2022.3.
- Полный набор bootstrap-сцен физически появляется после выполнения **Build Complete Three-Level Game** в целевом Editor. Если `MainMenu.unity` отсутствует, полная игровая версия ещё не подготовлена к запуску.
- Тесты в `EVIDENCE/TEST_RESULTS.md` сохраняют `NOT VERIFIED`, пока не выполнены фактические сценарии. Наличие кода не даёт права менять статус на `PASS`.
- Реальные Profiler-числа и вывод об оптимизации не записаны без сопоставимых снимков до/после. Никакие значения не предполагаются.
- Физическое мобильное устройство не проверено. Safe Area пока допускается подтверждать только честно обозначенной имитацией Editor.
- Внешний новый пользователь не привлекался. Текущий протокол честно фиксирует это; самостоятельная проверка не заменяет внешнюю.
- Матрица настоящих Editor/Game View/Profiler/Release-снимков может быть неполной до установки и запуска нужного Editor. Отсутствующие файлы должны быть перечислены в `EVIDENCE/MISSING_EVIDENCE.md`, а не заменены нарисованными изображениями Unity.
- Публичный remote и преподавательский доступ к репозиторию не настроены.

Актуальный статус каждого критерия следует брать из `EVIDENCE/FINAL_STATUS.md`, а не выводить из описания функций в этом README.
