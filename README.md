# Энергоключ

Версия 1.0.0

«Энергоключ» — единый учебный проект для УП.ПМ.12, ПП.ПМ.12, УП.ПМ.13 и ПП.ПМ.13 колледжа / Университета «Синергия». Это небольшая 2D-аркада с видом сверху: нужно собрать все энергетические кристаллы, не потерять три жизни и добраться до выхода. Закрытый выход не пропускает игрока, пока на уровне остаются кристаллы.

Персональные данные студента и титульные данные намеренно не заполнены.

## Среда

| Параметр | Значение |
|---|---|
| Unity | 6000.6.2f1 (Unity 6.6) |
| Шаблон | 2D |
| Язык | C# |
| Ориентация | landscape, обе горизонтальные ориентации разрешены |
| Базовое разрешение UI | 1280×720, `Scale With Screen Size`, match 0.5 |
| Версия продукта | 1.0.0 |
| Локальные сохранения | `PlayerPrefs` через `SaveService` |
| Проверенный физический компьютер | MacBook с Apple M3 |

Точная версия Editor записана в `ProjectSettings/ProjectVersion.txt`, версия продукта — в `ProjectSettings/ProjectSettings.asset`. Проект открывался в Unity 6000.6.2f1; для него получены снимки Editor, Game View и Profiler. Дополнительно macOS Standalone Development Build собран без ошибок/предупреждений и запущен на физическом MacBook Apple M3. Открывать и пересохранять проект более старым Editor не следует.

## Как запустить

1. В Unity Hub выберите **Add project from disk** и укажите корень `EnergoKey`.
2. Запустите проект в Unity 6000.6.2f1 и дождитесь окончания импорта.
3. Убедитесь, что в Console нет красных ошибок.
4. Откройте `Assets/Scenes/MainMenu.unity` и нажмите Play.

В репозитории уже находятся шесть сцен: `MainMenu`, `LevelSelect`, `Level1`, `Level2`, `Level3` и учебный `Prototype`. В Build Settings первой стоит `MainMenu`, затем выбор уровня и три игровые сцены; `Prototype` оставлен для показа этапа УП.ПМ.12.

Каждая сцена содержит `SceneBootstrap`. Он создаёт игровую иерархию и UI по имени сцены; основной код находится в `Assets/Scripts/Core/SceneBootstrap.cs`. Команды **EnergoKey → Build Complete Three-Level Game** и **EnergoKey → Prepare Final Visual Style** нужны для воспроизводимого восстановления сцен и настроек, а не для обычного запуска готовой копии.

## Игра

| Уровень | Кристаллы | Опасности | Когда доступен |
|---|---:|---:|---|
| 1 | 3 | 2 | сразу |
| 2 | 4 | 4 | после победы на уровне 1 |
| 3 | 5 | 6 | после победы на уровне 2 |

После победы на третьем уровне выводится финальный результат и кнопка возврата в меню. Перехода на уровень 4 нет.

В начале попытки у игрока три жизни. Опасность отнимает одну жизнь и возвращает игрока на старт; уже собранные в этой попытке кристаллы остаются собранными. При нуле жизней появляется Defeat. Restart заново загружает текущий уровень, но не удаляет общий прогресс.

Счёт рассчитывается так:

```text
score = collectedCrystals × 100 + remainingLives × 50
```

Лучший результат сохраняется после победы.

## Управление

- Сенсорное управление: четыре экранные кнопки со стрелками.
- В Editor: WASD или клавиши со стрелками.
- Пауза: кнопка Pause; продолжение — кнопка «Продолжить».

Пауза использует `Time.timeScale = 0`. Панель появляется на unscaled time, во время перехода блокирует повторные клики, а в скрытом состоянии не перехватывает ввод. Потеря фокуса или сворачивание приложения включает паузу; возврат фокуса сам игру не продолжает.

Editor-only клавиши F2–F6 и F8 помогают выставлять состояния для проверки и записи настоящих кадров. Они не входят в release-сборку и сами по себе не считаются результатом теста.

| Клавиша | Действие в Play Mode |
|---|---|
| F2 | открыть уровни 1–3 в локальном сохранении |
| F3 | собрать оставшиеся кристаллы |
| F4 | показать победу |
| F5 | показать поражение |
| F6 | проверить закрытый выход |
| F8 | включить или выключить имитацию Safe Area |

## Сохранения

`Assets/Scripts/Save/SaveService.cs` хранит четыре значения:

| Ключ | По умолчанию | Назначение |
|---|---:|---|
| `energokey.unlockedLevel` | 1 | максимальный открытый уровень, диапазон 1–3 |
| `energokey.bestScore` | 0 | лучший результат |
| `energokey.masterVolume` | 0.8 | общая громкость 0–1 |
| `energokey.tutorialSeen` | 0 | обучение пройдено или пропущено |

Новая попытка сбрасывает только данные текущего уровня. Повторный просмотр обучения не меняет открытые уровни и рекорд. Сохранение level 3, score 650, volume 0.37 и `tutorialSeen=true` подтверждено двумя независимыми Unity-процессами WRITE/READ; подробности — `EVIDENCE/PERSISTENCE_RESTART_PROBE.md`.

## Экраны и адаптация

Реализованы Main Menu, Level Select, Gameplay, Pause, Victory, Defeat, Settings, Tutorial и About. При первом запуске Tutorial показывает три карточки: управление, правило закрытого выхода, опасности и завершение игры. Кнопка «Как играть» всегда открывает обучение с первой карточки.

Canvas рассчитан на 1280×720. Unity PlayMode сформировал 21 фактический runtime-render: Main Menu, Level Select, Gameplay, Pause, Victory, Defeat и Settings при 1280×720 (16:9), 1440×720 (18:9) и 1024×768 (4:3). Для каждого состояния проверены границы видимых элементов и Safe Area. Обнаруженное пересечение подсказки и кнопки «Назад» в Level Select 4:3 исправлено и закреплено автоматической проверкой; кадры до/после находятся в `EVIDENCE/responsive`.

`SafeAreaAdapter` работает с `Screen.safeArea`; в Editor доступна имитация области 6% / 6% / 88% / 88%. Это проверка средствами Unity, а не испытание на физическом Android/iOS-устройстве.

## Проверки и доказательства

Сохранённый `EVIDENCE/EditModeTests-final.xml` содержит итоговый прогон Unity Test Runner: 24 из 24 EditMode-тестов прошли. `EVIDENCE/PlayModeTests-final.xml` содержит 17 из 17 пройденных runtime integration-тестов: управление, физические контакты, Restart, полный L1–L3 flow, UI, обучение, Pause, callback-логика фокуса, responsive renders и независимые кадры сохранений. Соответствующие логи завершились кодом 0.

Дополнительные фактические проверки:

- `EVIDENCE/PERSISTENCE_RESTART_PROBE.md` — PlayerPrefs между двумя последовательными независимыми Unity-процессами;
- `EVIDENCE/responsive/RESP_*.png` — 21 runtime-render, семь состояний × три разрешения;
- `EVIDENCE/MAC_STANDALONE_TEST.md` — macOS Standalone build с 0 errors/0 warnings и фактический runtime marker;
- `EVIDENCE/PROFILER_BENCHMARK.md` — детерминированный ProfilerRecorder benchmark до/после;
- `EVIDENCE/USER_ACCEPTANCE.md` — дословная пользовательская приёмка на MacBook M3 с честными границами.

Фактические результаты ручных и автоматизированных runtime-сценариев находятся в `EVIDENCE/TEST_RESULTS.md`, построчная сверка с заданием — в `EVIDENCE/FINAL_STATUS.md`. `EVIDENCE/REPORT_DATA.md` предназначен для подготовки Word-отчётов, а `EVIDENCE/FILE_MANIFEST.md` фиксирует состав поставки. Если результат нельзя было получить, он отмечен `NOT VERIFIED` и перечислен в `EVIDENCE/MISSING_EVIDENCE.md`.

Для проверки файлов без запуска Unity:

```text
python3 Tools/verify_deliverable.py
```

Этот скрипт проверяет структуру, размеры и комплектность. Он не подменяет прохождение игры, просмотр Console, тест на устройстве или наблюдение пользователя.

### Profiler

`EVIDENCE/screenshots/PP12_10_ProfilerBefore.png` и `PP12_11_ProfilerAfter.png` — реальные снимки Unity Profiler до и после перевода HUD с покадрового обновления на событийное. Их одиночные CPU-кадры сохранены как визуальное доказательство, но строгий вывод строится не по ним.

Для сопоставимого измерения выполнен детерминированный microbenchmark через `Unity.Profiling.ProfilerRecorder`: одинаковый harness, 120 кадров прогрева и 600 измеренных кадров на каждой ревизии, пять одинаковых изменений состояния. Полный HUD-marker вызывался 600 раз до и 5 раз после; суммарное время целевого marker — 1 845 755 ns и 57 749 ns соответственно, то есть уменьшилось примерно в 31.96 раза (на 96.87%). Это подтверждает сокращение работы HUD, но не обещает такое же ускорение полного кадра игры. Полный протокол, JSON, NUnit XML `ProfilerBenchmarkBeforeTests.xml` / `ProfilerBenchmarkAfterTests.xml` и логи `logs/profiler-benchmark-before.log` / `logs/profiler-benchmark-after.log` находятся в `EVIDENCE`.

Канонический полный hash финальной поставки определяется аннотированным тегом, который входит в Git-архив:

```text
git rev-parse pp-pm13-release^{commit}
```

Такой способ не оставляет в README самоссылочный hash, который изменился бы от самой правки README. Перед передачей нужно убедиться, что тег существует, указывает на `HEAD` и команда выводит ровно один 40-символьный hash.

Репозиторий локальный. GitHub/GitLab remote не настроен, поэтому публичный URL в документации не указан.

## Ограничения

- Физические Android/iOS-устройства и мобильные builds не проверялись. macOS Standalone успешно собран и запущен на физическом MacBook Apple M3, но MacBook не является мобильным устройством.
- Safe Area подтверждена имитацией и bounds assertions Unity, не системной Safe Area телефона/планшета.
- Потеря фокуса проверена и PlayMode-callback тестом, и реальным системным сворачиванием macOS Standalone: приложение открыло Pause и остановило таймер (`EVIDENCE/FOCUS_LOSS_TEST.md`).
- Внешний новый пользователь не привлекался. Пользователь-заказчик сообщил `PASS (USER-REPORTED)` на MacBook M3, но заранее знаком с заданием.
- ProfilerRecorder benchmark измеряет целевой HUD-marker, а не полное время кадра всей игры.
- Демонстрационное видео не создавалось; вместо него подготовлен допустимый storyboard на 80 секунд.
- Публичного Git remote нет.

`Library`, `Temp`, `Logs`, `obj`, `UserSettings`, `Build` и `Builds` исключены из Git и итогового ZIP. Актуальный итог по каждому требованию следует брать из `EVIDENCE/FINAL_STATUS.md`, а не выводить из списка функций в этом README.
