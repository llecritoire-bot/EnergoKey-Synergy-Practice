# Воспроизводимый ProfilerRecorder benchmark HUD

## Результат

Оба запуска завершились со статусом `PASS` в Unity `6000.6.2f1` на одном компьютере с процессором Apple M3. Временные worktree были созданы непосредственно из зафиксированных ревизий; существующие commit и tag не изменялись.

| Параметр | До оптимизации | После оптимизации |
|---|---:|---:|
| Git revision | `f616afd3be9b8586eba9f7d76af568f11bd2e9c3` | `2c60fe4ea10b9e95401f5909dffa915f09d407cd` |
| Реализация HUD | обновление каждый кадр | обновление по событию |
| Unity marker | `EnergoKey.HUD.PerFrameRefresh` | `EnergoKey.HUD.EventRefresh` |
| Измеренных кадров | 600 | 600 |
| Изменений состояния | 5 | 5 |
| Кадров с вызовом marker | 600 | 5 |
| Суммарное время marker | 1 158 419 ns | 40 085 ns |
| Среднее на каждый измеренный кадр | 1 930.70 ns | 66.81 ns |
| Медиана активного вызова | 1 709 ns | 7 792 ns |
| P95 активного вызова | 2 958 ns | 9 083 ns |

При фиксированном сценарии число кадров с полным обновлением HUD уменьшилось с 600 до 5. Суммарное время только измеренных HUD-marker уменьшилось примерно в 28.90 раза (на 96.54%). Отдельный событийный вызов после оптимизации тяжелее одного старого покадрового вызова; выигрыш получается за счёт радикального сокращения числа вызовов, а не ускорения одного обновления.

## Одинаковый сценарий

- 120 кадров прогрева, затем ровно 600 измеренных кадров Play Mode;
- один `GameController`, один `HUDController` и четыре одинаковых `UnityEngine.UI.Text`;
- состояние HUD не меняется, кроме пяти одинаковых вызовов `NotifyChanged` на кадрах 0, 120, 240, 360 и 480;
- один и тот же тестовый harness временно добавлялся в оба detached worktree;
- marker находился через `ProfilerRecorderHandle.GetAvailable` и измерялся `Unity.Profiling.ProfilerRecorder` на основном потоке;
- буфер считывался и очищался после каждого кадра, поэтому отсутствие marker в кадре учитывалось как ноль, а не как повтор последнего значения.

## Ограничения

Это детерминированный microbenchmark целевого HUD-marker, а не измерение полного времени кадра всей игры. Он не включает немаркированные операции, Editor UI и периодический timer-poll после оптимизации. Поэтому результат подтверждает сокращение работы полного обновления HUD в одинаковом сценарии, но не является обещанием ускорения всей игры на 96.54%.

Первоначальные GUI-снимки Profiler сохранены без изменений. Этот benchmark является дополнительным машинно-проверяемым доказательством и устраняет зависимость вывода от двух несопоставимых одиночных кадров GUI.
